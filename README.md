# hooks-guru

**husky + lint-staged for Rust** — install git hooks and run commands on staged files from one TOML config, as a library and a single-binary CLI.

Built around the same safety net as lint-staged: before tasks run, the repository is backed up in a stash and unstaged changes of partially staged files are hidden behind a patch; afterwards task modifications are staged, the unstaged changes are put back, and a failing task puts everything back the way it was. The glob engine is checked against picomatch: the test suite ships a corpus of 8,767 pattern/path pairs generated by picomatch 4.0.7, and every entry must match.

For teams that want pre-commit formatting and linting without a Node toolchain, and for Rust tools that need to run commands on staged files programmatically.

## Install

```sh
cargo install hooks-guru
```

## Quick start

`hooks-guru.toml` at the repository root:

```toml
[pre-commit]
"*.rs" = ["cargo fmt --", "cargo clippy --"]
"*.{json,yml,toml,md}" = "prettier --write"

[commit-msg]
commands = ["commitlint-guru --edit {}"]
```

```sh
hooks-guru install
```

That writes a shim per hook into `.githooks/`, points `core.hooksPath` at it, and from then on every `git commit` formats and lints exactly the files being committed.

```
✔ Preparing hooks-guru...
✔ Backed up original state in git stash (13f6168)
✔ Hiding unstaged changes to partially staged files...
✔ Running tasks for staged files...
✔ Applying modifications from tasks...
✔ Restoring unstaged changes...
✔ Cleaning up temporary files...
```

When a task fails you see its output and the repository is left exactly as it was:

```
✔ Running tasks for staged files...
  *.rs
    ✖ cargo clippy -- — failed with status 101

      error: unused variable: `x`

✖ 1 task(s) failed
✔ Reverting to original state because of errors...
✔ Cleaning up temporary files...
```

## Config

A hook is a table; every key that is not `commands` or `options` is a glob mapped to a command or an array of commands.

```toml
[pre-commit]
"*.rs" = "cargo fmt --"                       # lint-staged syntax: && chains sequentially
"*.ts" = "eslint --fix && prettier --write"
"!(*.spec).ts" = "eslint --fix"                # picomatch extglobs work
"src/{a,b}/**/*.css" = "stylelint --fix"
"*.md" = ["prettier --write", "markdownlint --fix"]

[pre-commit.options]
concurrent = true          # run glob groups in parallel
relative = false           # pass paths relative to the config directory
stash = true               # back the repository up before running tasks
hide_partially_staged = true
allow_empty = false        # fail when the tasks undo the whole commit
max_arg_length = 8191      # split many files into several invocations
diff = "HEAD~1"            # select files with other diff arguments
diff_filter = "ACMR"        # git status letters to keep

[commit-msg]
commands = ["commitlint-guru --edit {}"]     # {} is replaced by the hook arguments

[pre-push]
commands = ["cargo test"]
```

Globs without a slash match the file name (`*.rs` also matches `src/main.rs`); globs with a slash match the path relative to the config file. `commands` run once per hook after the file tasks, with `{}` replaced by the arguments git passes to the hook.

The same tables can live in the `[tool.hooks-guru]` section of `Cargo.toml`:

```toml
[tool.hooks-guru.pre-commit]
"*.rs" = "cargo fmt --"
```

`hooks-guru` finds `hooks-guru.toml`, `.hooks-guru.toml`, `.githooks.toml` or a `Cargo.toml` section by walking up from the current directory; `--config <file>` overrides the search.

## What happens around the tasks

1. Staged files come from `git diff --staged --raw -z --diff-filter=ACMR`; submodules and symlinks are skipped.
2. If the repository has commits, `git stash create` + `git stash store` save the whole state as a backup.
3. Files that are staged *and* have unstaged edits are saved to a patch (`git diff --binary --unified=0`) and reset to their staged content, so tasks only ever see what is about to be committed.
4. Tasks run with the files appended to the command. Groups run in parallel by default; commands inside one group run in order and stop at the first failure.
5. `git add` stages the task modifications of the matched files.
6. The patch is applied back with `git apply`, retried with `--3way`. If that fails, the backup stash is kept and the report tells you where it is.
7. The backup stash is dropped. If a task failed instead, `git reset --hard` + `git stash apply --index` restore the original state first.

Paths are passed to git through `--pathspec-from-file` with `--literal-pathspecs`, so file names with spaces, brackets or `$` are safe.

## CLI

```
hooks-guru run <hook> [options] [-- <hook arguments>]
hooks-guru install [--dir <path>] [--force]
hooks-guru uninstall [--dir <path>]
hooks-guru list
```

`run` options override the config: `--no-stash`, `--no-concurrent`, `--relative`, `--allow-empty`, `--no-hide-partial`, `--diff <args>`, `--diff-filter <letters>`, `--max-arg-length <n>`, `--verbose`, `--color`.

Exit codes: `0` when everything passed or nothing ran, `1` when a task failed, `2` for usage, config or git errors.

`install` refuses to overwrite a hook file it did not create unless `--force` is given. `uninstall` removes only the shims that point at this `hooks-guru` binary.

Commands are split the way lint-staged splits them (no shell): quotes group arguments, `&&` inside the config chains commands. For shell features wrap the command: `sh -c "..."`. On Windows bare names like `npm` are resolved through `PATHEXT`, so `npm run lint` works without writing `npm.cmd`.

## Library

```rust
use hooks_guru::{Config, GitRepo, ProcessExecutor, run_hook};

let config = Config::parse(r#"[pre-commit]
"*.rs" = "cargo fmt --"
"#)?;
let hook = &config.hooks["pre-commit"];
let repo = GitRepo::discover(std::env::current_dir()?)?;

let report = run_hook(&repo, "pre-commit", hook, &repo.top_level, &[], &hook.options, &ProcessExecutor::default());
println!("{}", report.render(true));
assert!(report.ok());
```

Anything that implements `Executor` can run the tasks, which makes the whole workflow testable without spawning processes:

```rust
use hooks_guru::{CommandResult, Executor, TaskCommand};

struct Recorder;

impl Executor for Recorder {
    fn execute(&self, command: &TaskCommand) -> CommandResult {
        CommandResult { code: Some(0), spawn_error: None, output: format!("ran {command}") }
    }
}
```

`hooks_guru::Glob` is the picomatch-compatible matcher on its own:

```rust
use hooks_guru::Glob;

assert!(Glob::new("*.rs")?.is_match("src/main.rs"));
assert!(Glob::new("!(*.spec).ts")?.is_match("src/a.ts"));
assert!(!Glob::new("{a,b}/**/*.css")?.is_match("c/x/a.css"));
```

## Differences from lint-staged

- Config is TOML, not JavaScript; function tasks are not supported.
- Multiple config files in a monorepo are not merged: one config per run, with paths relative to its directory.
- If restoring unstaged changes fails, the backup stash is kept instead of being dropped.
- Letter ranges with a step (`{a..c..2}`) expand correctly; picomatch expands them incorrectly.
- Multiple brace groups in one pattern (`{a}{b}`) are supported; picomatch does not match them.
